Isolated server runtime

乾淨隔離環境已通過四組月／火星搜尋回歸與 CUDA 運算檢查。正式服務尚未切換；這是同一伺服器、既有資料的重現證據。

A new virtual environment on server 192.168.31.145 uses Python 3.10.20 without shared site-packages. All 35 installed application dependency artifacts are recorded with exact wheel URLs and SHA-256 hashes. Pip reports no broken requirements.

Verified behavior

  • Four historical Moon/Mars queries reproduce candidate IDs, centers, common numeric ranking fields and query DEM heights.
  • Model SHA matches the frozen baseline. Index provenance matches the current live service and every underlying file hash; the historical baseline predates this field.
  • Mars imagery coverage, uncovered imagery response and invalid-coordinate rejection pass.
  • CUDA forward/backward agrees with an analytic gradient. Geometry crop, orientation and invalid-extent checks pass.

Limits and deployment status

The production service remains on its original environment. This is not a fresh-machine or full training reproduction. Base Python still comes from the server's Conda installation; operating-system, native-library, GPU-driver and complete training-data provenance remain incomplete. CUDA computation passes, but NVML initialization still warns. A dependency-consistent environment is not a security audit or proof that every optional endpoint works.

The lock targets Linux x86_64, CPython 3.10 and Torch CUDA 11.8. Pip and setuptools bootstrap versions are recorded separately. No human scoring is required.
